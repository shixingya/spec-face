spec-face 试用台 v0.0.0

证件照和工牌不是"好看就行"——过不了规格就是废图。这里把编号、规格和校验做成可以点的东西。 资产共 —。
试用台 全量编号图鉴 GitHub 仓库 ↗

1先定合规规格 S

先问用途，再谈审美。用途决定规格，规格决定构图，构图决定提示词——顺序颠倒就会返工。

⚠ 本规格标记 needs_verification：正式提交前请比对受理方（使领馆、出入境、交管、平台）的最新公告，本页不构成官方口径。

2选岗位气质，说这个人长什么样 P · W · B · E

外貌只写客观特征：性别年龄段、脸型、发型、肤色、胖瘦。气质形容词不用你写，编号 — 和岗位库负责。

着装 / 背景光型 / 神态——不选就按岗位推荐组合自动补全

3把你手上的图拉回规格校验 本机计算，不上传

尺寸、宽高比、体积、底色取样全部在浏览器里算；图片不出这台设备，页面也不发任何网络请求。测不了的项一律标 −，不算通过。

把图片拖进来，或
校验项用第 1 步选定的规格实测

4要真出图：把照片交给本机的开源服务 G

网页不能替你渲染——那需要显卡和模型权重。这一步按你上面的选择生成命令，复制回本机就能跑；没有 GPU 时用 G-06，它只导出提示词与请求体，交付动作由你完成。

    这个后端需要什么
    
    
    三道闸门写死在代码里，不在数据里
    
      
      
    • 没有真实照片（--photo）就拒跑——凭文字生成一个不存在的人，那是写真需求。
      • 
      
    • 没有写明授权（--confirm-authorized）就拒跑，并拒绝一切"用生成的照片去过门禁 / 活体检测 / 实名认证"的用法。
      • 
      
    • 请求体里没有身份注入节点（PuLID / InstantID / IP-Adapter / ReActor）就拒跑——没有身份注入的文生图必然画出"更好看但不是本人"的人，而"像不像本人"是工牌头像唯一的通过条件。
      • 
      
    • 端点默认只允许 127.0.0.1；接云端 API 等于把人脸上传给第三方，必须你自己显式加 --allow-remote。
